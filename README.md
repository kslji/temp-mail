# Temp Mail Backend

A disposable/temporary email backend, similar in concept to temp-mail.org:
generate a random inbox, receive real email sent to it, read it via an API,
and let it auto-expire.

## How it works

Two processes run side by side:

1. **`run_smtp.py`** — a real SMTP server (via `aiosmtpd`) that accepts inbound
   mail for your configured domain(s) and stores it in the database.
2. **`uvicorn app.main:app`** — the FastAPI REST API a frontend uses to create
   inboxes and read messages.

Both share the same SQLite database (swap for Postgres in production by
changing `TEMPMAIL_DATABASE_URL`).

```
Internet ──MX──> run_smtp.py (port 25/1025) ──> DB <── FastAPI (port 8000) <── your frontend
```

## Quick start (local testing, no domain needed yet)

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # edit if you want, defaults work for local testing

# terminal 1
python run_smtp.py

# terminal 2
uvicorn app.main:app --reload --port 8000
```

Create an inbox:
```bash
curl -X POST "http://localhost:8000/api/inbox?local_part=myname"
# -> {"address": "myname@example-temp.test", ...}
```

Send it a test email locally (since example-temp.test isn't a real domain,
you can't get real internet mail to it yet — but you can send directly to
your local SMTP server to simulate it):
```python
import smtplib
from email.mime.text import MIMEText
msg = MIMEText("hello world")
msg["From"] = "someone@example.com"
msg["To"] = "myname@example-temp.test"
msg["Subject"] = "Test"
with smtplib.SMTP("127.0.0.1", 1025) as s:
    s.send_message(msg)
```

Read it back:
```bash
curl "http://localhost:8000/api/inbox/myname@example-temp.test/messages"
```

## Going live once you buy a domain

1. Buy the domain (e.g. `mytempmail.com`).
2. Add an **MX record** pointing at your server, e.g.:
   `mytempmail.com.  MX  10  mail.mytempmail.com.`
   and an A record for `mail.mytempmail.com` -> your server's IP.
3. On the server, run `run_smtp.py` bound to **port 25** (needs root, or grant
   the capability: `sudo setcap 'cap_net_bind_service=+ep' $(which python3)`).
   Set `TEMPMAIL_SMTP_PORT=25` in `.env`.
4. Set `TEMPMAIL_DOMAINS=mytempmail.com` in `.env`.
5. Put the API behind a reverse proxy (nginx/Caddy) with HTTPS for your
   frontend to call.
6. Consider adding: rate limiting, SPF/DMARC records (mainly relevant if you
   also send mail, not required just to receive), and moving from SQLite to
   Postgres for concurrent load.

## API reference

| Method | Path | Description |
|---|---|---|
| GET | `/api/domains` | List domains available for new inboxes |
| POST | `/api/inbox?local_part=&domain=` | Create an inbox (random address if `local_part` omitted) |
| GET | `/api/inbox/{address}` | Inbox info / expiry |
| POST | `/api/inbox/{address}/refresh` | Extend inbox lifetime |
| DELETE | `/api/inbox/{address}` | Delete inbox + its messages |
| GET | `/api/inbox/{address}/messages` | List messages (summary) |
| GET | `/api/messages/{id}` | Full message (text/html body, attachments) |
| DELETE | `/api/messages/{id}` | Delete a single message |
| GET | `/api/attachments/{id}/download` | Download an attachment |

Interactive docs are auto-generated by FastAPI at `/docs` once the API is running.

## Notes on abuse & responsible use

Disposable-email services are commonly used for legitimate privacy reasons
(avoiding spam, testing signups), but they can also be abused to bypass
email verification on other services. If you launch this publicly, consider:
rate-limiting inbox creation per IP, blocking outbound relay entirely (this
service only *receives* mail, it doesn't send — by design there's no
`handle_MAIL`/relay logic here), and having an abuse-reporting contact.

## Extending

- **Real-time updates**: add a WebSocket endpoint in `app/main.py` that
  pushes when a new `Message` is inserted (e.g. via a simple pub/sub or
  polling the DB every few seconds and diffing).
- **Multiple domains in the UI**: `/api/domains` already returns the list
  configured in `TEMPMAIL_DOMAINS`; have the frontend let users pick one,
  matching temp-mail.org's domain dropdown.
- **Custom local part / "change address" button**: already supported via
  `local_part` query param on `POST /api/inbox`.
